# Handoff: страница трека и страница тренировки (Neskuchka)

## Overview

Редизайн двух экранов фронтенда `healthy-heroes/neskuchka`:

- `/workouts` — страница трека: шапка трека, сегодняшняя тренировка в фокусе, история по неделям;
- `/workouts/$workoutId` — страница тренировки: полный протокол с раскрываемыми упражнениями, боковая шпаргалка.

Плюс дизайн-система 0.1 поверх Mantine (палитра, шрифтовая пара, дефолты компонентов) и готовый `theme.ts`.

Главная задача, под которую собран экран трека: **человек заходит, сразу видит сегодняшнюю тренировку и начинает её**. Всё остальное (история, прогресс) — ниже и мельче.

## About the Design Files

Файлы в `designs/` — **дизайн-референсы, написанные в HTML**. Это прототипы, показывающие итоговый вид и поведение, а не production-код для копирования. Разметка в них написана в собственном шаблонном формате (`<x-dc>`, `sc-for`, `sc-if`, `support.js`) и намеренно вся на инлайновых стилях — это особенность среды прототипирования, не рекомендация по стилю.

Задача разработчика: **воспроизвести эти экраны в существующем окружении проекта** — React 19 + Mantine 9.5 + TanStack Router/Query, CSS-модули на компонент, как уже сделано в `frontend/src/components/*`. Инлайновые стили из прототипов переносить не нужно: собирать из мантиновских `Card`, `Button`, `Badge`, `Group`, `Stack`, `Grid`, а специфику — в `*.module.css` с мантиновскими CSS-переменными.

Файлы открываются в браузере напрямую (двойной клик по `.dc.html`), интерактив работает: переключение состояний дня в 2a, раскрытие упражнений на странице тренировки.

## Fidelity

**High-fidelity.** Цвета, типографика, отступы, размеры и состояния финальные — воспроизводить попиксельно. Все значения продублированы ниже в разделе Design Tokens и в `theme.ts`.

Одно исключение: изображения. Картинка к тренировке в макетах — это дроп-зона (`<image-slot>`), настоящих изображений нет. См. раздел Assets.

## Interactions & Behavior

**Страница трека**
- Клик по строке истории → `/workouts/$workoutId`.
- «Начать тренировку» → страница тренировки (в будущем — режим прохождения).
- «Отметить выполненной» → optimistic-обновление: карточка переключается в состояние «выполнена», сегмент в полосе прогресса меняет цвет с `#30525c` на `#c35727` и высоту 16px → 10px, счёт «8 из 12» инкрементится. «Отменить отметку» — обратно.
- Раскрытий/аккордеонов на треке нет: сегодняшняя тренировка всегда развёрнута, остальные — строки.
- Четыре состояния дня (в макете переключаются чипами над экраном, в проде — данные):
  1. **середина недели, тренировка есть, не отмечена** — карточка + кнопки; в «этой неделе» ниже только прошедшие дни (19, 17);
  2. **тренировка отмечена** — пилюля «Выполнено» в тёмной шапке, вместо кнопок плашка со временем;
  3. **на сегодня тренировки нет** — вместо протокола текст «На сегодня тренировки нет — новая появится, когда её опубликуют» + компактная карточка последней тренировки со сводкой и кнопкой «Открыть 20 августа» + ссылка «Наверстать пропущенную 19 августа»;
  4. **начало недели (тренировка сегодня — первая в неделе)** — блок «Эта неделя» показывает заглушку «Кроме сегодняшней на этой неделе тренировок пока не было».

**Страница тренировки**
- Клик по любой из трёх ячеек строки упражнения раскрывает/сворачивает панель; подсказка меняется «как делать» ↔ «свернуть». Одновременно могут быть раскрыты несколько.
- По умолчанию раскрыто первое упражнение главной секции (в макете — швунг). Решить на реализации: либо всё свёрнуто, либо первое упражнение комплекса.
- Правая колонка липкая (`top: 84px` — под sticky-шапкой 60px + 24px зазор).
- Анимация раскрытия в макете отсутствует; при реализации — Mantine `Collapse` с дефолтной длительностью (200ms, ease).

**Адаптив.** Экраны спроектированы под десктоп с фиксированной рабочей шириной 1240px. Мобильная версия в этот заказ не входит — ниже 1240px окно скроллится по горизонтали.

**Загрузка.** Использовать существующий подход: `WorkoutCardSkeleton` уже есть в проекте, добавить скелетоны для карточки «Сегодня» (тёмная шапка + 3 строки) и блока прогресса.

**Пустые состояния.** Трек без тренировок вообще — состояние в макете не нарисовано, требуется решение продукта. Отмеченный кейс «на сегодня тренировки нет» покрыт (см. состояние 3).

## State Management

Локальное состояние экранов:
- `openExercises: Record<exerciseId, boolean>` — раскрытые упражнения на странице тренировки.
- Отметка «выполнено» — мутация TanStack Query с optimistic update и инвалидацией списка тренировок трека.

Данные (TanStack Query, как сейчас в `Workouts.tsx` / `WorkoutView.tsx`):
- трек по slug;
- список тренировок трека — **нужен параметр окна** (последние 30 дней) для блока прогресса, плюс постраничная история по неделям;
- одна тренировка по id, с описаниями упражнений.

**Чего сейчас нет в бэкенде и что понадобится** (`backend/app/store`, `app/domain`):
1. Отметка выполнения: `workout_completion { user_id, workout_id, completed_at }` + эндпоинты post/delete.
2. Агрегат прогресса за окно: количество опубликованных и выполненных за 30 дней, дата последней выполненной, общее число тренировок в треке.
3. Картинка тренировки — одно необязательное изображение (`Workout.ImageURL`).
4. Справочник упражнений с контентом: `description`, `cues: string[]`, `easier`, `harder`, `video_url`. Сейчас в `Exercise` только название.
5. Предписание (`prescription`) как свободная строка на упражнение в секции: «10», «3х1 мин», «3х(1+2) @ 70%», «2 @ 70%» + «3х2 @ 80%» — то есть массив строк, а не число повторений. Модель должна это выдерживать.
