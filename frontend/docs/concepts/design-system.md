# Дизайн-система и Claude Design

## Зачем

На [claude.ai/design](https://claude.ai/design) экраны рисуются не абстрактным html,
а **нашими компонентами с нашей темой**. Чтобы это работало, дизайн-систему надо туда
загрузить — этим занимается команда `/design-sync` в Claude Code. Результат правок
на канвасе возвращается обратно в репозиторий и переводится в код.

Storybook при этом — **не витрина, а источник правды**: конвертер рендерит каждую стори
дважды (в референсном сторибуке и в собранном бандле) и сравнивает скриншоты, пока они
не совпадут. Чего нет в сторибуке — того нет в дизайн-системе.

## Из чего собрана

| Слой | Где | Что это |
|---|---|---|
| Тема | `src/theme.ts` | палитра, типографика, шкалы, умолчания компонентов |
| Образцы | `src/design/specimens/` | тема, показанная глазами: рампы, шкалы, примитивы |
| Компоненты | `src/components/`, `src/pages/` | обычный код приложения |
| Вход | `src/design/index.ts` | barrel: что экспортировано — то существует в системе |
| Сборка | `vite.ds.config.mjs` → `dist-ds/` | один ESM-модуль + один CSS |
| Конфиг синка | `.design-sync/config.json` (корень репо) | shape, entry, titleMap, provider |

Образцы — настоящие компоненты, а не разметка внутри стори: у карточки в панели
дизайн-системы должен быть экспорт в бандле, иначе её не с чем сопоставить.

## Круг работы

### 1. Собрать бандл и референсный сторибук

```
mise run //frontend:ds-bundle
mise run //frontend:ds-reference
```

Обе таски пишут туда, где их ищет конвертер: бандл в `frontend/dist-ds/`, референс
в `.design-sync/sb-reference/` **от корня репозитория**, а не от `frontend/`. Сторибук
собирается локальным бинарём — `npx storybook` тянет свежую версию, и её загрузчик
пресетов падает на наших прибитых аддонах.

### 2. Залить

```
/design-sync
```

Скилл ставит свои esbuild / ts-morph / playwright + chromium в `.ds-sync/`, собирает
превью каждой стори, скриншотит их рядом с референсом и итерирует, пока не сойдётся.
Первый прогон долгий — каждый компонент проверяется и грейдится. Повторные дешёвые:
нетронутые компоненты ничего не стоят, оценки переносятся.

### 3. Рисовать

На канвасе. Проект уже знает наши компоненты, тему и шкалы.

### 4. Вернуть в код

```
/design import <url-проекта>
```

кладёт файлы в рабочий каталог. Либо просто дать ссылку Claude Code — он читает проект
напрямую и переводит в код на ветке.

### Повторный синк

После правок в теме или компонентах: пересобрать бандл, пересобрать референс
(если менялись стори или исходники), снова `/design-sync`.

## Правила

**Стори должны быть детерминированными.** Сравнение идёт скриншотами: два рендера одной
стори обязаны совпадать пиксель в пиксель. Поэтому `createTrackWorkouts()` выдаёт
фиксированные ID и даты — статус выполнения считается по хешу ID (`utils/completion`),
и со случайными ID полоса прогресса каждый раз разная.

**Экспорт в barrel обязателен.** Компонент без строчки в `src/design/index.ts` агент
на канвасе не увидит, даже если у него есть стори.

**Поверхность Mantine реэкспортируется целиком.** `MantineProvider` должен приезжать
из бандла: две копии Mantine — два контекста темы, и превью разъезжается с приложением.

**Титул стори маппится на экспорт.** Совпадает — ничего делать не надо; не совпадает
(`Foundation/Colors` → `ColorRamps`) — строчка в `titleMap` конфига.

**Обёртка превью повторяет `App.tsx`.** Всё, что приложение делает до рендера —
`MantineProvider` с темой, `DatesProvider`, `dayjs.locale('ru')`, импорты шрифтов, —
продублировано в `.storybook/preview.tsx` и в barrel'е. Забыть локаль дешевле всего:
компоненты отрендерятся, но даты приедут по-английски, и дизайн-система будет описывать
не тот продукт.

**Шрифты инлайнятся в CSS бандла.** Страница на claude.ai/design не отдаёт наши woff2,
а без Oswald система приезжает с чужой типографикой.

## Ловушки

- `provider` в конфиге **заменяет** декораторы `.storybook/preview.tsx` как обёртку
  превью на следующей сборке. После его правки тематизированный компонент надо
  перепроверить сравнением: неполная дистилляция ломает то, что декораторы рендерили
  нормально, а перенесённые оценки этого не поймают.
- `ExerciseRow` объявлен как `display: contents` и живёт только внутри грида
  `WorkoutSections`. Его стори берёт настоящий грид из чужого CSS-модуля — копия грида
  разъедется с оригиналом на первой правке.
- Диагностика скилла говорит кодами: `[GRID_OVERFLOW]` лечится `overrides.<Name>.cardMode`,
  `[CAPTURE]` — авторским превью в `.design-sync/previews/<Name>.tsx`, `[ZERO_MATCH]` —
  глобом стори в конфиге сторибука.
- Коммитим из `.design-sync/` только `config.json`, `NOTES.md` и `previews/`.
  Остальное — сборочный мусор, он в `.gitignore`.
