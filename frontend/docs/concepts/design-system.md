# Дизайн-система и Claude Design

## Что это

Экраны рисуются на [claude.ai/design](https://claude.ai/design) **нашими компонентами
с нашей темой**, а не абстрактным html. Для этого дизайн-система загружена туда как
настоящий код.

Storybook в этой схеме — **не витрина, а эталон**. Конвертер рендерит каждую стори
дважды: в референсном сторибуке и в собранном бандле, — и сравнивает скриншоты, пока
они не совпадут. Чего нет в сторибуке, того нет в дизайн-системе.

---

## Два вида проектов — не путать

| | Дизайн-система | Дизайн-проект |
|---|---|---|
| Что это | склад компонентов и токенов | холст, где рисуют экраны |
| Кто наполняет | `/design-sync` из репозитория | ты и агент на канвасе |
| Сколько | одна | сколько угодно |
| Тип | `PROJECT_TYPE_DESIGN_SYSTEM` | `PROJECT_TYPE_PROJECT` |

Наша дизайн-система: **https://claude.ai/design/p/7936765d-eb40-4689-9706-51c21668f9ba**

**Рисовать внутри дизайн-системы нельзя.** Следующий `/design-sync` приводит её в точное
соответствие сборке из репозитория и снесёт всё лишнее. Тип задаётся при создании
и не меняется.

**Один проект — одно исследование.** «Лендинг», «Workout — варианты», а не «Дизайн».
Причина механическая: проект читается и импортируется целиком, и если в нём лежат три
несвязанные затеи, они приедут вперемешку. Проекты дешёвые, неудачный просто бросается.

Проект — это не макет. Агент собирает **работающий интерфейс**: живой React из нашего
бандла, который кликается. Поэтому «внедрить» — это не «сверстать по картинке», а
перенести в наш рантайм: настоящие пропы вместо фикстур, роутер, запросы к API,
стили по нашим правилам. Композиция и решения приезжают готовыми, обвязка — нет.

Известные проекты — в `.design-sync/NOTES.md`, раздел **Дизайн-проекты**.

## Сценарий 1: перерисовать экран

Самый частый. Кода не касается.

1. Создать **новый дизайн-проект** и подключить к нему нашу дизайн-систему.
2. Рисовать. Агент собирает из наших компонентов — они там все.
3. Дать Claude Code **ссылку на проект**. Этого достаточно: он читает дизайн-проекты
   напрямую. `/design import <ссылка>` тоже работает и дополнительно кладёт файлы
   в рабочий каталог — нужно, если хочешь их версионировать.
4. Дальше это обычная задача: ветка, правки, PR.

**Ссылку придётся дать руками.** Сам Claude Code твои дизайн-проекты не найдёт: он
перечисляет только дизайн-системы.

**Скажи одной фразой, что это.** По файлам видно, какой экран нарисован и из чего
собран, но не видно намерения: замена текущему экрану или эксперимент рядом; что
финально, а что черновик; тянуть ли правку общего компонента в остальные экраны.

**Ничего пересинкать не надо.** Синк нужен только когда менялся код.

## Сценарий 2: поменял тему или компонент в коде

Дизайн-система разъедется с репозиторием, если не пересинкать.

```
mise run //frontend:ds-bundle      # бандл дизайн-системы
mise run //frontend:ds-reference   # референсный сторибук
```

Потом в Claude Code набрать `/design-sync`. Он сам разберётся, что изменилось:
нетронутые компоненты пропустит, изменённые перепроверит скриншотами.

**Обе сборки запускать вместе.** Пересоберёшь одну — конвертер сравнит новый бандл
со старым эталоном и напишет `[REFERENCE_STALE?]`. Оценки при этом будут врать.

---

## Сценарий 3: добавить компонент в систему

Три шага, все обязательные:

1. **Стори** — `<Component>.story.tsx` рядом с компонентом.
2. **Экспорт** — строчка в `src/design/index.ts`. Без неё агент компонент не увидит,
   даже если стори есть.
3. Пересинк по сценарию 2.

Если титул стори не совпадает с именем экспорта (`Foundation/Colors` → `ColorRamps`) —
добавить пару в `titleMap` в `.design-sync/config.json`. Ключ — **последний сегмент**
титула, не весь путь.

## Правила, которые нельзя нарушать

**Стори должны быть детерминированными.** Сравнение идёт скриншотами: два рендера одной
стори обязаны совпасть пиксель в пиксель. Поэтому фикстура `createTrackWorkouts()` даёт
фиксированные ID и даты — статус выполнения считается по хешу ID (`utils/completion`),
и со случайными ID полоса прогресса каждый раз разная.

**Никаких девтулзов и плавающих панелей в `StoryPreview`.** Всё с `position: fixed`
вылезает за пределы ячейки карточки. Один такой элемент ломает **все** карточки сразу.

**Обёртка превью повторяет `App.tsx`.** Сейчас это `DatesProvider` → `MantineProvider`
с темой, плюс `dayjs.locale('ru')` и импорты шрифтов. Продублировано в трёх местах:
`.storybook/preview.tsx`, `src/design/index.ts` и `provider` в `.design-sync/config.json`.
Разъедутся — превью и приложение будут выглядеть по-разному. Забыть локаль дешевле
всего: компоненты отрендерятся, но даты приедут по-английски.

**Картинки для стори — в `src/`, а не в `public/`.** `public/` в бандл дизайн-системы
не попадает: путь отвалится, и вместо фотографии будет заглушка. Импортировать модулем
(`import avatar from '@/api/fixtures/avatar.jpg'`) — сборка сама подставит data-URL.

**Длинные страницы — с `viewport` в оверрайдах.** Кадр по умолчанию 700px, потолок —
2000px. Что не влезает, обрезается молча. Страница длиннее 2000px не проверяется
целиком; вариант — сократить фикстуру, как сделано в стори `Workouts`.

## Если сломалось

| Что видно | Что случилось |
|---|---|
| Все превью пустые, в консоли `Dynamic require of "react"` | сборка дизайн-системы уехала в ESM. Формат должен быть CJS |
| `[TITLE_UNMAPPED]`, компонентов ноль | не выпустились `.d.ts` или не переписались алиасы `@/`. Проверить, что `build:ds` отработал целиком |
| `MantineProvider was not found` в одном превью | стори тянет вторую копию Mantine. Лечится `storyImports.shim` |
| `[GRID_OVERFLOW]` на всех карточках | что-то с `position: fixed` попало в `StoryPreview` |
| Карточка обрезана снизу | нужен `overrides.<Name>.viewport` |
| `[REFERENCE_STALE?]` | пересобрана только одна из двух сборок |

Подробности каждого случая — в `.design-sync/NOTES.md`. Там же секция
**Re-sync risks**: что может тихо протухнуть.

## Где что лежит

| Файл | Что это |
|---|---|
| `src/theme.ts` | палитра, типографика, шкалы — источник правды |
| `src/design/index.ts` | вход дизайн-системы: что экспортировано, то существует |
| `src/design/specimens/` | карточки самой темы: рампы, шкалы, примитивы |
| `vite.ds.config.mjs` | сборка бандла (CJS, react внешний, шрифты инлайном) |
| `tsconfig.ds.json` + `scripts/ds-dts-paths.mjs` | декларации и переписывание алиасов |
| `.design-sync/config.json` | настройки синка: формат, entry, titleMap, провайдер, viewport'ы |
| `.design-sync/conventions.md` | шапка README дизайн-системы — её читает агент на канвасе |
| `.design-sync/NOTES.md` | грабли и риски пересинка |

Из `.design-sync/` коммитим только эти три файла и `previews/`. Остальное —
сборочный мусор, он в `.gitignore`.
